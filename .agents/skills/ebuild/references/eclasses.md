# Eclass Reference

## Where to find eclasses

All Gentoo eclasses live at `/var/db/repos/gentoo/eclass/`. Read them directly with the Read tool when you need to understand a specific function, variable, or behavior. This is the authoritative source — always prefer reading the eclass over guessing.

## distutils-r1 (Python packages)

```ebuild
DISTUTILS_USE_PEP517=hatchling   # required: backend name
PYTHON_COMPAT=( python3_{13..15} )
inherit distutils-r1 [pypi]
```

### DISTUTILS_USE_PEP517 values

Full `build-backend` → value mapping: see `workflows/python.md` Step A.

Extra values not in pyproject.toml mapping:
- `standalone` — no backend, custom build script
- `no` — old-style pre-PEP517 package (avoid)

### Key variables
- `DISTUTILS_EXT=1` — set if package has C/Rust extensions
- `DISTUTILS_OPTIONAL` — don't set src_* phases automatically
- `DISTUTILS_SINGLE_IMPL` — only one Python version (rare)
- `PYTHON_USEDEP` — use in dep atoms: `dev-python/foo[${PYTHON_USEDEP}]`

### Key functions
```ebuild
distutils_enable_tests pytest    # most common; sets up RESTRICT and BDEPEND
distutils_enable_tests unittest  # stdlib unittest
distutils_enable_sphinx docs     # Sphinx documentation

# Per-implementation test override
python_test() {
    local EPYTEST_DESELECT=(
        tests/test_broken.py::test_case
    )
    epytest
}

# Per-implementation install
python_install_all() {
    distutils-r1_python_install_all
    dodoc README.md
}
```

### PYTHON_COMPAT ranges
```ebuild
python3_{13..15}        # python 3.13, 3.14, 3.15
pypy3_11                # PyPy 3.11
pypy3_11 python3_{13..15}   # both
```

## pypi (PyPI source URL helper)

```ebuild
inherit pypi   # auto-sets SRC_URI and S
```

- Sets `SRC_URI` to sdist tarball from PyPI
- Sets `S` to `${WORKDIR}/${P}` (normalized)
- `PYPI_PN="${PN/-/_}"` — override if PyPI name differs from `${PN}` (e.g., underscores)
- `PYPI_NO_NORMALIZE=1` — disable name normalization

## cargo (Rust packages)

```ebuild
CRATES="
    crate-name@1.2.3
    another-crate@4.5.6
"
inherit cargo
```

**Always generated by `pycargoebuild`, never written by hand.**

### Key variables (set before inherit)
- `CRATES` — list of `name@version` pairs (generated by pycargoebuild)
- `CARGO_CRATE_URIS` — auto-generated SRC_URI fragment from CRATES

### Key functions
```ebuild
src_configure() {
    # Pass features to cargo
    local myfeatures=( feature1 $(usex gui gui '') )
    cargo_src_configure --no-default-features
}

src_compile() {
    cargo_src_compile
}

src_install() {
    cargo_src_install   # installs all binaries from target/release/
    dodoc README.md
}

src_test() {
    cargo_src_test
}
```

### System library deps for common -sys crates
| Crate | Gentoo dep |
|---|---|
| `openssl-sys` | `dev-libs/openssl:=` |
| `zlib-sys` | `sys-libs/zlib:=` |
| `libz-sys` | `sys-libs/zlib:=` |
| `sqlite3-sys` | `dev-db/sqlite:=` |
| `libgit2-sys` | `dev-libs/libgit2:=` |
| `curl-sys` | `net-misc/curl:=` |
| `pkg-config` (build) | `virtual/pkgconfig` in BDEPEND |

Add `DEPEND="${dep}:="` and `RDEPEND="${DEPEND}"` for linked libs.

### GIT_CRATES (git-sourced crates)

pycargoebuild generates `declare -A GIT_CRATES=(...)` for crates sourced from git.
Place it **before** `inherit cargo`. The eclass downloads the tarballs and generates
`[patch.'git_url']` entries in `${ECARGO_HOME}/config.toml` to redirect git sources
to local paths.

**Double-patch chain caveat**: If the workspace Cargo.toml has `[patch.crates-io]`
pointing a crate to a git URL (e.g., `crate = { git = "...", rev = "..." }`), the
eclass config-level `[patch.'git_url']` **does not intercept** it — cargo tries to
fetch the git URL and fails offline. Fix in `src_prepare()`:
1. Patch the Cargo.toml to replace the git reference with a local `path = "..."`.
2. Delete `Cargo.lock` so cargo regenerates it offline from the patched sources.

Direct git deps in `[dependencies]` (not via `[patch.crates-io]`) are handled
correctly by the config-level patch without any extra work.

```ebuild
src_prepare() {
    local arrow="${WORKDIR}/repo-commitshorthash"
    local s1="s|git = \"https://github.com/owner/repo\"[^}]*}|path = \"${arrow}\" }|"
    sed -i -e "${s1}" Cargo.toml || die
    rm Cargo.lock || die
    default
}
```

```ebuild
src_configure() {
    local mycmakeargs=(
        -DENABLE_TESTS=$(usex test ON OFF)
        -DBUILD_SHARED_LIBS=ON
        -DENABLE_FEATURE=$(usex feature)
    )
    cmake_src_configure

src_compile() {
    cmake_src_compile
}

src_install() {
    cmake_src_install
}
```

- `CMAKE_BUILD_TYPE` defaults to `RelWithDebInfo`
- `BUILD_DIR` — out-of-source build dir (set automatically)
- Use `usex flag ON OFF` for boolean cmake options

## Applying Patches (all build systems)

Patches go in `files/` next to the ebuild. Naming convention: `${PN}-${PV}-description.patch`.

### PATCHES array (preferred, EAPI 6+)

```ebuild
PATCHES=(
    "${FILESDIR}/${PN}-1.2-fix-build.patch"
    "${FILESDIR}/${PN}-1.2-disable-werror.patch"
)

# If you need nothing else in src_prepare, omit the function entirely —
# default() is called automatically and applies PATCHES + eapply_user.

# If you DO override src_prepare, you must call default (or eapply_user manually):
src_prepare() {
    default    # applies PATCHES array then calls eapply_user
    # additional modifications here
    sed -i 's/bad/good/' configure.ac || die
}
```

### eapply (manual, when you need ordering control)

```ebuild
src_prepare() {
    eapply "${FILESDIR}/${PN}-1.2-fix-a.patch"
    eapply "${FILESDIR}/${PN}-1.2-fix-b.patch"
    eapply_user    # MUST call explicitly when not using default()
}
```

**Rule**: always end with either `default` or an explicit `eapply_user` call — never
skip it, or user patches (`/etc/portage/patches/`) won't be applied and pkgcheck
will warn.

### Generating a patch from the extracted source

```bash
# 1. Copy the file to patch
cp "${WORKDIR}/${P}/path/to/file.c" /tmp/file.c.new

# 2. Edit /tmp/file.c.new with your fix

# 3. Generate unified diff
diff -u "${WORKDIR}/${P}/path/to/file.c" /tmp/file.c.new \
    > /usr/local/portage/CATEGORY/PKGNAME/files/${PN}-${PV}-description.patch

# 4. Verify with dry-run
patch -p1 --dry-run -i .../files/${PN}-${PV}-description.patch \
    -d "${WORKDIR}/${P}/"
```

The diff header paths must match what `-p1` strips (one leading component). GitHub-style
diffs (`a/path/to/file`) work with `-p1` by default.

## autotools

```ebuild
inherit autotools
```

```ebuild
src_prepare() {
    default          # apply PATCHES array + eapply_user
    eautoreconf      # only if configure.ac was patched
}

src_configure() {
    local econfargs=(
        $(use_enable nls)
        $(use_enable threads)
        $(use_with ssl openssl)
        --disable-static
    )
    econf "${econfargs[@]}"
}
```

Helper functions: `use_enable`, `use_with`, `use_if_iuse`.

## rebar3 (Erlang packages)

```ebuild
inherit rebar3
```

The eclass automatically adds:
- `RDEPEND="dev-lang/erlang:="` and `DEPEND="${RDEPEND}"`
- `BDEPEND="dev-util/rebar:3 >=sys-apps/gawk-4.1"`

### Key functions provided

| Function | What it does |
|---|---|
| `rebar3_src_prepare` | Removes rebar.lock, replaces `{deps,[…]}` with `{deps,[]}`, sets vsn |
| `rebar3_src_compile` | Runs `rebar3 as default release --all` |
| `rebar3_src_install` | Installs from `_build/default/lib/${PN}` or `rel/${PN}` |
| `rebar3_install_lib <dir>` | Installs ebin/, include/, priv/ (skips symlinks!) |
| `erebar3 <targets>` | Runs rebar3 with correct ERL_LIBS and HEX_OFFLINE=true |

### NIF packages — src_install override required

rebar3 creates `priv/` and `include/` as **symlinks** in `_build/default/lib/`.
`rebar3_install_lib` skips symlinks. Always override `src_install` for NIF packages:

```ebuild
BDEPEND="dev-build/cmake"

src_install() {
    rebar3_src_install
    local dest="$(get_erl_libs)/${P}"
    insinto "${dest}/priv"
    doins "${S}"/priv/*.so
    # If headers exist:
    insinto "${dest}/include"
    doins "${S}"/include/*.hrl
}
```

### REBAR_APP_SRC

Defaults to `src/${PN}.app.src`. Override if the app name differs from `${PN}`:
```ebuild
REBAR_APP_SRC="src/myapp.app.src"
```

## pkg_postinst Patterns

### Informational messages

```ebuild
pkg_postinst() {
    elog "Run 'myapp --init' to initialise the database."
    elog "Config file: /etc/myapp/config.toml"
    ewarn "Breaking change in 2.0: rename foo.conf to bar.conf"
}
```

| Function | Color | Use for |
|----------|-------|---------|
| `einfo` | green | Neutral info (less persistent than elog) |
| `elog` | white | Persistent install-time messages (shown on next `emerge`) |
| `ewarn` | yellow | Non-fatal warnings |
| `eerror` | red | Errors (use `die` to abort instead if fatal) |

### optfeature — suggest optional packages

```ebuild
inherit optfeature

pkg_postinst() {
    optfeature "JSON support" dev-libs/json-c
    optfeature "SSH backend" net-libs/libssh2 net-libs/libssh
    # second arg onwards = alternative atoms (user picks one)
}
```

Prints: `"For JSON support, install dev-libs/json-c"` only when the package is
not already installed. More precise than a raw `einfo`.

### System users and groups

Use the `acct-user` / `acct-group` eclass pattern — **never** call `useradd`
directly in an ebuild.

```ebuild
# In DEPEND/RDEPEND (user pkg creates the account at install time):
RDEPEND="acct-user/myapp acct-group/myapp"

# The acct-user/myapp ebuild (separate package) looks like:
EAPI=8
inherit acct-user
ACCT_USER_NAME="myapp"
ACCT_USER_GROUPS=( myapp )
ACCT_USER_HOME="/var/lib/myapp"
ACCT_USER_SHELL="/sbin/nologin"
acct-user_add_deps
```

For packages that still use the legacy `enewuser`/`enewgroup` API:

```ebuild
inherit user

pkg_setup() {
    enewgroup myapp
    enewuser myapp -1 /sbin/nologin /var/lib/myapp myapp
}
```

## common-lisp-3 (Common Lisp library packages)

```ebuild
inherit common-lisp-3
```

Installs ASDF source files into `/usr/share/common-lisp/source/${CLPACKAGE}/`
and symlinks `.asd` files into `/usr/share/common-lisp/systems/` so SBCL/CLISP/etc.
can locate them.

Automatically adds `PDEPEND="virtual/commonlisp"`.

### Key variables
- `CLPACKAGE` — package subdirectory name, defaults to `${PN}`; override when the ASDF system name differs
- `CLSOURCEROOT` — `/usr/share/common-lisp/source` (read-only, for reference)
- `CLSYSTEMROOT` — `/usr/share/common-lisp/systems` (read-only, for reference)

### Key functions
```ebuild
common-lisp-install-sources .            # install all sources recursively from CWD
common-lisp-install-sources -t lisp src/ # install only .lisp files from src/
common-lisp-install-asdf                 # symlink all .asd files in CLSYSTEMROOT
common-lisp-install-one-asdf foo.asd     # symlink a single .asd
```

`common-lisp-3_src_compile` is a no-op. `common-lisp-3_src_install` calls
`common-lisp-install-sources .` + `common-lisp-install-asdf`. Override `src_install`
when you need finer control (e.g., drop test systems).

### Standalone binary packages (SBCL save-lisp-and-die)

When a CL project compiles to a standalone binary, do NOT use `common-lisp-3`.
All Lisp deps belong in BDEPEND (baked into the image); only C FFI libs in RDEPEND.
See `workflows/common-lisp.md` for the full pattern.

```ebuild
BDEPEND="dev-lisp/sbcl dev-lisp/ironclad dev-lisp/cl-sqlite ..."
RDEPEND="dev-db/sqlite:3"

src_compile() { sbcl --script build.lisp || die; }
src_install() { dobin bin/${PN}; }
```
